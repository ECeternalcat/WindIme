# WindIme 后续实施路线图

创建日期：2026-07-23  
执行原则：按编号顺序推进；可靠性和可观测性优先于新增输入功能。  
状态标记：`待处理`、`进行中`、`已完成`、`受阻`。

## 1. Rime 状态指示器

状态：进行中

进度：代码实现及 JVM 单测、Debug APK 构建已完成；待 701KC 验证候选栏显示、fallback 连续可用及新输入会话采用 Rime 后再标记完成。

目标：用户能明确知道当前中文输入后端及词库部署状态。

状态集合：

- 轻量词库：正在使用纯 Java fallback。
- 雾凇准备中：正在解包、启动或部署 schema。
- 雾凇已就绪：native Rime 已部署并被当前输入会话采用。
- 雾凇部署失败：解包、JNI、schema 部署或超时失败，继续使用 fallback。

验收标准：

- 状态持久化，设置页和 IME 候选栏读取同一来源。
- 后台线程只更新状态，不直接操作 View。
- 输入法不可用时不影响 Java fallback。
- 候选栏提示简短，不挤占三层候选空间。

## 2. Rime 部署管理页

状态：进行中

进度：管理页、空间统计、破坏性操作确认、维护排队及进程级安全门控已完成；待 701KC 验证 D-Pad/OK/BACK 和全新进程启动维护后再标记完成。

目标：把词库信息、缓存维护和用户学习数据分开管理。

计划功能：

- 显示当前状态、数据版本和内置词库组成。
- 显示共享源词典、Rime 编译产物、用户学习数据占用。
- 重新部署：下次全新应用进程启动时清理共享数据和编译缓存，然后重新部署。
- 清理编译缓存：不清除用户学习数据。
- 清除用户学习：独立危险操作，不能与重新部署混用。

验收标准：

- 不在 native Rime 正在运行时直接删除其文件。
- 维护操作通过“待处理标记”在下一次全新进程的安全启动阶段执行；单纯 Service 重建但 native 仍存活时继续延后。
- 所有破坏性操作有确认对话框。
- 全程支持 D-Pad、OK、BACK。

## 3. 701KC 性能基线

状态：待处理

目标：记录首次解包、首次部署、内存、存储、冷启动和按键延迟。

验收标准：

- 记录设备、系统版本、APK 版本和词库版本。
- 分别记录 fallback 可用时间与 Rime 就绪时间。
- 测量部署前后应用数据占用和峰值内存。
- 验证后台部署期间不会阻塞输入或被系统频繁杀死。

## 4. 按键校准热刷新与冲突检查

状态：待处理

目标：校准结果安全、明确并及时生效。

验收标准：

- 同一 KeyCode/ScanCode 重复绑定时阻止保存并高亮冲突项。
- 校准允许取消、重试和恢复默认。
- 新映射在下一输入会话自动 reload；可行时通知正在运行的 Service。

## 5. 真机回归场景固化

状态：待处理

目标：建立每次发布前必须执行的 701KC 回归清单。

场景包括：

- 输入框快速切换和多应用切换。
- 共享 BACK/退格从删除到关闭再恢复系统返回。
- 桌面快捷键从 iWnn 秒切换到 WindIme。
- 来电、锁屏、解锁、前后台切换。
- Rime 部署中输入与部署完成后的会话切换。
- 符号、定型文、用户词和五种输入模式。

## 6. 候选翻页

状态：待处理

目标：候选超过可视数量时仍可通过 D-Pad 连续访问。

验收标准：

- 左右键在窗口边界继续移动到下一组候选。
- 显示当前位置或页码。
- 第二层拼音和第三层词候选分别保留焦点。
- 刷新候选后不会提交旧索引。

## 7. Rime 词频学习确认

状态：待处理

目标：确认选词后 Rime 学习记录正确更新。

验收标准：

- 重复选择低位候选后，其排序能合理提升。
- 用户词置顶不会破坏 native 候选索引或学习对象。
- 重复文本候选具有明确提交和学习策略。

## 8. 英文 T9 接入新词库

状态：待处理

目标：利用已内置的 `en + en_ext`，替换当前约 1,099 词的小表。

建议方案：构建阶段生成紧凑的 T9 索引，运行时不扫描 YAML。

验收标准：

- 英文常用词、缩写和互联网词显著扩充。
- 首次英文输入无明显加载卡顿。
- 索引生成可复现，并记录源文件哈希。

## 9. 首字母大写与按键反馈落地

状态：待处理

目标：使现有设置真正影响输入行为。

验收标准：

- 英文句首大写设置生效。
- 震动、声音、无反馈三档生效。
- 不重复触发系统自带按键音或震动。

## 10. Tencent 联网扩展词库

状态：待处理

目标：默认不内置，用户可选下载、部署和删除。

验收标准：

- 下载前检查剩余空间。
- 显示进度，支持取消和失败重试。
- 下载后校验 SHA-256，再进入部署流程。
- 部署失败可回滚，不影响默认 `base + ext`。
- 删除扩展后恢复默认 schema，用户学习数据处理策略明确。

## 11. Rime 生命周期

状态：待处理

目标：明确 native Rime 初始化、同步和退出的唯一所有者。

验收标准：

- 在安全时机同步用户数据。
- Service 重建不会启动多个冲突 maintenance 会话。
- 不在后台部署线程运行时贸然调用 `exitRime()`。

## 12. 可复现 JNI 构建

状态：待处理

目标：摆脱无法追溯的单一预编译 `.so`。

验收标准：

- 固定 Trime、librime、依赖库和 NDK commit/version。
- 记录 ABI、编译参数、许可证和产物 SHA-256。
- 至少可重复生成当前 `armeabi-v7a` 产物。

## 13. 许可证与发布流程

状态：待处理

目标：统一管理应用及第三方组件的开源义务。

验收标准：
